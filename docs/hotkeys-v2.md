# 本地快捷喊话 v2

## 已实现与待实测

2026-10-04 用户确认前一版 8 KiB 文案库在游戏中工作正常。这是用户报告，非自动化运行时测量。

v2 候选容量 65536 字节，消息条数 1～512。每条可选择 Ctrl、Alt、Shift、~ 的非空组合和一个主键：字母、数字、F1～F24、小键盘数字、方向键、PageUp/PageDown/Home/End/Insert/Delete。危险系统组合和重复组合拒绝保存；不支持 Win、裸键、聊天确认等按键。单条保护保持 50 个 UTF-16 单位，不自动拆分或连发。

本机 v2 已安装并回读三文件／安装状态（2026-10-04），默认原样迁移二十条，二进制库 2296 字节。备份基线仍是用户确认可用的 v1。游戏内发送和组合键实际效果尚未实测，不能把安装校验当成游戏验证。

原生面板和原二十条数组不是新版消息的索引来源。所有文案和组合键来自本地 `messages.json` 编译出的 `hotkeys-v2.bin`。默认迁移保留二十条原文及 ~+数字／F 键，不改用户文案。

候选 DLL：`4AE8AB0793EEBCEA5E23C1B8931A6C0057393BBCF413A9AF323D91750D3EE143`。

回退基线 v1 DLL：`BEB422999A6E8E7F87D93937D9010B15DCAAACCE237FD7B11C280D5CF88CCA10`。

候选只针对当前用户路径和原始组件版本。修改后签名摘要失效；测试不证明 WeGame 或游戏允许加载该组件，遇拒绝应恢复，不规避验证。真实组合键发送、不同键盘布局／输入法以及新版游戏兼容仍需人工测试。

## 数据与处理

源文件是平面 UTF-8 JSON：version=2，title，count，每条 `"0"`/`"bind0"` 等成对字段。保存前检查完整结构、转义后重复字段、Unicode 代理对、重复组合、长度及控制字符；不静默丢字。

二进制采用小端格式：

| 字段 | 大小 |
| --- | --- |
| `LPSKEY2\0` | 8 字节 |
| 整文件长度 | uint32 |
| 条数 | uint32 |
| 每条 VK、修饰位 | uint16 + uint16 |
| 每条文案 UTF-8 长度 | uint32 |
| 每条 UTF-8 文案和 NUL | n + 1 字节 |

修饰位 Ctrl=1、Alt=2、Shift=4、~=8。全库容量包含这些开销，不是“65536 个汉字”。名称保留在可编辑源中，不作为发送记录。

短响应第一个字段 `_lps_keys_v2` 携带长度/FNV-1a32 标记。FNV 是一致性检测，不是认证；安装和恢复另外使用 SHA-256 及版本锁定。2046 字节传输、原发送函数和游戏单条限制不改。原接收解析器仅收到安全的二十条空兼容项和“使用本地编辑器”标题，不解析长文案。

接收时一次读取和完整校验二进制，失败禁用发送。缓存固定容量、代码 RX／数据 RW 分离。原键盘回调跳转至新处理：Windows 标准 API 获取修饰键状态，精确匹配，主键按下仅触发一次，主键释放清除去重；焦点变化重置去重。发送前复制选中文案，释放非阻塞原子门，再调用原发送函数，避免发送回调重入死锁。原发送函数在 `0x180019FFB` 同步复制输入到自己的字符串，栈内副本无需跨调用保存。

代码只运行于原 WeGame 输入/喊话回调路径，不另建全局热键服务，不模拟文本输入，不读取游戏运行内存，不进行运行时 DLL 注入。快捷键不会吞掉原游戏事件，按键冲突应由用户自行调整。

## 安装安全

只接受已知 v1 DLL、已知加载器及与 v1 安装记录一致的库／响应。旧 DLL、旧响应和旧 v1 库分别按哈希备份，再部署新库、DLL、短响应并回读。

保存源文件可以在游戏运行时进行；应用和安装必须完全退出相关进程。管理入口使用具名互斥锁，拒绝同时执行两次安装／应用／恢复。每个文件替换有暂存校验和目标哈希 CAS，失败回退只覆盖本事务确认的结果，不覆盖并发未知改动；手动恢复会另存当前数据，保留 v2 源文件与库。

`Restore-Pallas-Hotkeys.cmd` 恢复上述 v1 三文件基线，不恢复原始十条，不恢复加载器。旧 v1/二十条状态及备份不改动。已恢复的状态不会被重装悄悄覆盖，重装需要复核。
