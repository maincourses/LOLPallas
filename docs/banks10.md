# 八组十条／数字键／无单条字数上限

2026-10-05，用户确认四组二十条版将新增文案缩短后可以发送，并要求每组十条、去掉 F 键发送及工具自己的单条字数上限。本版已备份安装并回读；未启动游戏或发送测试消息，新分组和长文案等待用户在新训练局验证。

## 使用

现有八十条按原顺序分成八组，第 1 组为 1～10 条，第 2 组为 11～20 条，依次到第 8 组的 71～80 条。初始第 1 组；按住原面板键（当前为 `~`）并按下、松开一次 PageDown 切下一组，PageUp 切上一组，首尾循环。组内 `1～9、0` 分别选第 1～10 条；F1～F10 不调用喊话发送函数，也不屏蔽游戏自身按键作用。

重新启动 WeGame，开启“一键喊话”，进入**新的训练局**。先测第一组 `~+1`，然后 `~+PageDown`、`~+1` 应发送原第十一条；再翻一次发送原第二十一条，开头为“容量检验第二十一条”。`~+PageUp` 返回上一组。翻页本身不发送，按住不重复切组，切组后不必松开 `~`。**原面板预览仍为第一组，不会显示当前组号**，请以实际发送文字判断。

编辑双击项目根目录 **`Open-Banks10-Editor.cmd`**。在表格选择消息，下方编辑完整文案，表格只显示短预览及当前长度，不限制单条字数。八十条固定槽位和分组按键不可在本编辑器增加／重绑；这次只改变分组大小和长度检查。

- **保存文案**：保存专用草稿，可在游戏运行时做；不会自动改变正在运行的游戏。
- **保存并应用**：先保存草稿，然后备份并应用到本地 JSON；需要先关闭游戏和客户端，并从托盘彻底退出 WeGame，再启动新局。
- **读取已应用文案**：读取运行库；有未保存修改会询问是否放弃。
- 草稿位置为 `%LOCALAPPDATA%\LOLPallasPortable\Editor\banks10-messages.json`，与旧现代版 `messages.json` 分开；不会覆盖后者。不存在草稿时编辑器读取当前已应用库。

不要点旧现代 EXE 的“安装／启用”或“保存并应用”，也不要再用 `Set-Pallas-Banks80-ShortText.ps1` 修改本版。后者是旧四组版的长度对照工具，现暂停。

## 上限的准确含义

本版取消 **工具自己的 50／100 UTF-16 单位限制**：编辑器、JSON 保存／应用及新原生发送前检查不再按消息字符数拒绝。完整消息不截断、不拆成多条、不连发。

仍保留 **整套 UTF-8 JSON 65536 字节** 上限及结构／合法 UTF-8／空文案／控制字符检查。它包含所有文案及 JSON 字段、转义、标题，不等于每条可用 65536 字节，更不是无限容量。原生文本扫描最多到现有整库分配边界（含 NUL），这是内存读取保护，不是另加一个字符数量门槛。

长文案的原生 2046 字节短预览传输不扩大：预览单项最多显示前 32 个 UTF-16 单位加省略号，正确避开半个代理对；完整文本仍由已有本地读取器读入。**缩短的是预览，不是实际发送文案**。长度/FNV 标记同步匹配完整库。

这些变化**不修改或绕过英雄联盟／WeGame 原发送函数或服务器的单条限制**。它们仍可能拒绝、截断或异常；用户此前手动长输入曾闪退。建议先验证短文案和新分组，再逐步加长；发不出／闪退时停止，不反复发送。没有宣称任何长度已在游戏安全通过。
