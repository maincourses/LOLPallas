# 固定二十键回退对照版

2026-10-05 用户报告此对照版仍失败，随后仅恢复了腾讯签名有效的原版 DLL；该实验组件目前停用。恢复前 DLL／状态记录另存于 `backups\original-dll-restore-*`，原始基线和个人文案不变。`pallas.exe` 尚未恢复，不能把当前测试称为完整原版环境。恢复脚本状态标记为 `original-dll-restored`，旧实验入口会拒绝覆盖，避免误重装。

本次仅用于排查 v3 游戏内无响应：撤销独立组合键对原键盘回调的替换，恢复已成功的 8 KiB 二十条版同一段原生键盘处理指令。不是完整恢复旧版 DLL，不能提前宣称游戏内成功。

- 文案库格式仍为 v3，缓冲区仍为 65536 字节；不修改当前运行文案、编辑草稿或路径设置。
- 固定二十条：按住 `~`，主键 `1～9、0` 发送第 1～10 条，`F1～F10` 发送第 11～20 条。松开主键可再发。
- 本地接收器必须同时把二十条填入原生文案数组，否则后十个原生 F 键无文案可发。因此接收器投影由十条扩为二十条；原发送函数不变。
- 当前仍使用 WeGame 的原生面板键状态；助手需启用一键喊话，并选择 `~`。不支持独立组合键或新增／删除条目。面板仍不是二十条编辑器。
- 单条保留 50 个 UTF-16 单位保护；这不是测得的游戏最大长度。

## 使用

安装后双击项目根目录 `Open-NativeKeys-Editor.cmd`。消息内容可编辑；快捷键列只读，新增、删除和录制按钮停用。保存文案仅更新本地草稿；保存并应用仍需完全退出游戏、客户端及 WeGame。随后手动启动 WeGame，在训练模式验证 `~` 面板、`~+1` 及 `~+F10`。

旧独立键位 EXE 以及旧版 Apply／Restore 入口不兼容此对照组件，应使用上述专用入口。它们的哈希检查会拒绝未知组件，不能绕过。此任务不制作新的分享 EXE。

## 备份与版本

`Manage-Pallas-NativeKeys.ps1 -Mode Install -AcceptUnsignedExperiment` 仅接受已记录、完全一致的修复 v3 组件。正常退出检查、同用户校验、版本锁定、互斥、原子替换和失败回滚仍有效。

安装备份留在 `%LOCALAPPDATA%\LOLPallasPortable\backups`：

- `upgrade-*\TenPallas.previous.dll` 与 `state.previous.json` 保留紧邻本次安装前的组件和状态。
- `editor-before-nativekeys-*.json` 保留本次安装前的编辑草稿。
- 原安装 `backup_id` 和最初还原基线不变。本机该基线是 v2，不是已成功的 8 KiB v1；不得混用旧还原命令或声称它能恢复成功版。

候选 DLL SHA-256：`C7457983D5B09B8F1A4D4770F4386E5750077D1A29B4F285D1ABDFC83615C5CB`。

## 验证边界

离线原生指令对比、二十条中文和转义字符接收、文件错误禁用、原 IAT／64 KiB 布局、自己编译的正常 Windows 加载夹具，以及安装／应用／失败回滚夹具已通过。测试不加载腾讯 DLL、不访问游戏进程、不发送消息。文件回读不能证明真实加载或发送，游戏内状态仍为未验证。

修改组件的签名摘要仍失效。若更新、签名、完整性或反作弊检查拒绝加载，应停止使用并恢复，不绕过检查。
