# 面板和全部快捷键无响应：本次定位

## 已确认的故障阶段

本机 `pallas.tlg` 采用固定记录头和 UTF-16 XOR 编码，普通文本搜索读不到内容。只读解析使用已安装 `tx_log.dll` 中的原有表；没有操作游戏进程、调用云端接口或发送消息。诊断只返回必要事件，不返回账号、令牌或文案。

北京时间 2026-10-05 00:40 的原版测试：运行标志 `ten_pallas_run_flg=3`，出现 `SendGetShoutMessage` 和 `OnGetShoutMessageRsp, send chat content to tp`。01:33 的修改版测试：一键喊话设置为 1，但运行标志为 0，也没有这些文案下发事件。当前安装文件、状态和运行库的摘要均一致，原版 `pallas.exe` 的签名有效。

这证明故障早于正常文案下发，组件未报告运行。仅靠按键处理／放大文案长度的修复不能解决这个阶段的问题。运行标志为 0 并不能进一步证明是签名拒绝、Windows 加载失败还是初始化未完成，不能据此宣称其中某一种已经确证。

整库 65536 字节是允许的容量，不是当前实际文件大小；当前库只有 737 字节。不能因此把失败直接归咎于“发送了 64 KiB 数据”。

## 本次兼容性对照候选

曾成功的 8 KiB 二十条版不移动原导入表；后来的独立按键版本追加 USER32 描述符并移动导入表。当前对照候选取消这个布局变化：保留原导入目录、所有原 IAT 槽和描述符字节；使用原来就导入的 `GetModuleHandleW`、`GetProcAddress` 查询已加载 USER32 中的正常公共 API。缺失 API 时停止发送，不加载别的模块。

保留 64 KiB、512 条上限、单条 50 UTF-16 单位保护、事件按键匹配、原有发送包装和本地文案格式。仍不改 `pallas.exe`、不扩大 IAT 为代码可写、不增加注入器、不关闭安全保护。新候选摘要 `3632DDE9...14377F`，安装会额外备份当前候选，保持原版恢复基线和全部文案。

这是针对加载兼容性的单项对照，**还不是已经确认解决的根因**。只有新的训练模式日志显示组件运行、文案下发，并且用户实际看到消息，才能称为本机发送验证成功。如果正常加载被完整性／安全保护拒绝，必须停止并恢复，不绕过。

本机已于北京时间 2026-10-05 02:00 在进程退出检查后安装该对照 DLL。额外备份位于 `LOLPallasPortable/backups/upgrade-760c8888c2e94365803ffdfa055d74d7`；安装前后的运行文案、已应用源 JSON、编辑草稿、路径设置和原版启动器摘要完全相同。原版 DLL 的恢复基线保留。尚无新局运行或发送结果。

## 如何验证与恢复

彻底退出游戏和 WeGame 后安装兼容性测试版，再正常从 WeGame 进入训练模式。按住 `~` 查看面板，再 `~+1`；独立组合键另测。点编辑器“安装状态”可读取最近一局的 `RunFlag`、`SchemeDispatched` 和 `MatchesCurrentInstall`。旧局的成功记录不能证明新安装成功；下发成功也不是游戏发送成功。

如果仍失败，保留当前日志，不继续反复修改容量／按键。编辑器“还原组件”恢复安装前的原版 DLL，并保留原版启动器、文案和所有备份。故障定位脚本 `tools/Read-Pallas-Log.py` 为开发机只读工具，不作为普通用户运行依赖。
