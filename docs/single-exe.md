# 单文件 EXE 测试版

当前候选是 `LOLPallas-LoadCompat-Test-日期.exe`，双击打开中文编辑器；不需要自行解压 ZIP，不需要 Python、编译器或 Codex。要求 64 位 Windows 10/11 及其系统 Windows PowerShell 5.1／.NET Framework；组件兼容性仍由固定 SHA256 约束。游戏内发送未验证前，不作为已可用版本推荐给别人。

## 使用

1. 双击 EXE。只有编辑器和自身运行资源准备，不会自动安装组件。
2. 点“选择 WeGame”，选择包含 `apps\Pallas` 的 WeGame 根目录。自动检测失败也可直接选择；路径只需设置一次。
3. 有旧 `messages.json` 时点“导入文案”，检查文案和快捷键；否则使用公共默认二十条。导入只改变编辑区，保存后才持久化。
4. 退出英雄联盟、客户端和托盘里的 WeGame，点“安装／启用”。阅读风险并确认，必要时使用同一 Windows 用户的正常 UAC 提权。
5. 后续修改点“保存并应用”，手动打开 WeGame 并开启“一键喊话”。先在训练模式测试。

本版增加“已恢复原版后重新安装”兼容：只接纳同用户、同目录、原版哈希和签名及恢复备份都匹配的已知记录，不删旧记录、不跳过检查。重新安装仅替换 `TenPallas.dll`，`pallas.exe` 保持原版；旧状态和全部历史备份保留，并用当前原版 DLL 建立新的还原基线。以后点“还原组件”会回到原版 DLL，而不是早期 v2 实验版。

这种重装先沿用已应用的运行文案及键位，不以默认文案或编辑草稿覆盖它们。如果编辑区有尚未应用的改动，重装成功后另点“保存并应用”。无需删除 AppData、文案、安装记录或备份。启动 EXE 和本次构建都不自动安装组件。

界面包含增删消息、录制快捷键、保存、应用、安装状态、安装／启用、还原组件、导入／导出文案和说明。不在 WeGame 原生面板编辑本地文案。

旧 v3 用户也需要使用新 EXE 点一次“安装／启用”，仅“保存并应用”不会升级组件。升级保留当前已应用的文案、键位以及最初的还原备份，不把编辑区的草稿自动应用。确认草稿后可以另点“保存并应用”。升级后不要继续用旧 EXE 操作安装。

默认按住 `~` 可查看原生前十个 `~+数字` 槽位的预览；面板不展示全部独立组合键。消息按本地库的实际键位发送。切换窗口时若仍按着快捷键，请松开后重新按下，避免把恢复焦点时的自动重复当作一次新发送。

EXE 可以移动、改名或直接发给朋友。各用户的文案、路径设置、操作结果及备份在 `%LOCALAPPDATA%\LOLPallasPortable`，不会写回 EXE、不会随 EXE 分享。编辑源在其 `Editor\messages.json`，路径设置在 `Editor\settings.json`，组件与运行库沿用 v3。可用“导出文案”另存 JSON。

EXE 内置的自有脚本、公共模板和二进制差异，会在首次运行时按校验表释放到当前用户目录的版本化 `App\...` 缓存；并非完全不落地的程序。以后每次运行验证缓存，缺失或被修改则拒绝执行，不悄悄覆盖、不关闭保护。无需保持 EXE 与其他外部文件在一起。

仍是非官方实验版，EXE 自身未作可信代码签名，安装后 WeGame 组件的签名摘要也失效，可能被安全或完整性检查拒绝、有加载及账号风险。不要关闭／绕过安全或反作弊保护。异常时退出游戏和 WeGame，用“还原组件”，保留所有个人文案和备份。未知版本拒绝安装，更新后的未知组件拒绝强行还原。

**此前的 v3 修复及二十键回退对照均报告游戏内无响应；恢复两个原版组件后，用户报告原版一键喊话正常。本次只修复安装状态迁移，并未修复或验证游戏内发送。** 新包沿用候选 DLL `52776E...0CC0AD`，原版 `pallas.exe` 加该 DLL 的实际效果、新电脑首次加载及独立组合键仍待测试。64 KiB 整库、最多 512 条、单条 50 个 UTF-16 单位保护不变。

## 实现与开发验证

`tools/desktop/LOLPallasApp.cs` 是普通 .NET Framework x64 GUI 子系统宿主，内嵌透明 ZIP 资源及其摘要，不使用混淆／加壳或网络下载。启动后验证嵌入资源及白名单，只提取自有文件；不分发完整腾讯 DLL／EXE或私人文案。缓存路径拒绝网络、重解析及越界路径，原子搬入自身版本目录，不递归删除任何目录。

宿主调用系统 PowerShell 的中文 WinForms 编辑器，无黑色命令窗口。安装／还原由同一 EXE 的固定动作入口通过正常 UAC 执行；严格校验 SID、动作、同意标记、用户源文件路径及唯一任务 ID，以结构化结果回传。组件写入继续使用 v3 的备份、版本校验、进程保护、互斥与异常回退。启动、编辑、路径选择和导入／导出不需要改组件，也不会发真实游戏消息。

宿主仅为自己的 Windows PowerShell 5.1 子进程设置系统模块搜索路径，避免从 PowerShell 7／终端启动时继承不兼容模块，导致 `Get-AuthenticodeSignature` 无法加载。不改用户或系统环境变量，不关闭签名／保护检查。EXE 的 16 项自测包含污染模块路径下的系统 Security 模块导入和对自有无签名测试脚本的真实签名 API 调用。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/Build-Standalone.ps1
```

构建使用 Windows 自带 C# 编译器和本机已核验的 v3 二进制差异。编译后运行 EXE `--self-test`：只在新临时目录解包和测试，不开可见窗口、不修改真实安装、不加载腾讯 DLL。另运行路径设置及共享 GUI／v3 事务回归。交付报告记录产物 SHA256、离线检查、未签名和游戏内未验证状态。

修复候选通过 8 项格式测试、159 项隔离原生逻辑检查、17 项真实文件读取检查和 62 项便携安装事务检查。另用自编最小 DLL 的 3 项正常 Windows 加载检查复现旧导入布局失败、验证修复布局；这项测试不加载腾讯 DLL，不能替代真实 WeGame／游戏验证。

重装兼容另通过 65 项隔离检查，覆盖历史二十键／v2 基线记录、原版重建基线、运行文案与草稿保留、还原和再次启用、坏备份／外部改动／账号和路径不匹配拒绝，以及状态写入前后失败的回滚。EXE 内嵌文件逐项校验，仍不包含个人文案或完整腾讯组件。
